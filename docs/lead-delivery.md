# KODERA — подключение заявок

Формы на главной странице и /contact отправляют JSON в `POST /api/contact`. Калькулятор /pricing передаёт выбранный проект в /contact через параметры URL. **Без настройки приёмника API возвращает 503**, и пользователь не получает ложное подтверждение отправки.

## Настройка

1. Создайте `.env.local` на основе `.env.example` (не добавляйте реальные секреты в Git).
2. Укажите `KODERA_LEADS_WEBHOOK_URL` — HTTPS-адрес своего обработчика заявок (например, защищённый endpoint системы автоматизации или CRM).
3. Если приёмник поддерживает Bearer, укажите `KODERA_LEADS_WEBHOOK_TOKEN`. Он хранится **только на сервере**.
4. Перезапустите Next.js и отправьте тестовую заявку. Убедитесь, что она действительно появилась в системе-получателе.
5. В production задайте `NEXT_PUBLIC_SITE_URL` в виде абсолютного адреса своего сайта, иначе sitemap остаётся пустым.

## Пример сообщения для приёмника

```json
{
  "event": "kodera.lead",
  "receivedAt": "2026-10-22T12:00:00.000Z",
  "name": "Тест",
  "contact": "test@example.org",
  "market": "ru",
  "service": "Корпоративный сайт",
  "budget": "Нужна оценка",
  "message": "Нужен сайт с каталогом услуг и заявкой.",
  "source": "/contact"
}
```

Приёмник должен вернуть HTTP 2xx **только после подтверждения приёма**. Любой другой статус отображается как ошибка, без обещания доставки.

## Ограничения до публичного запуска

- Текущая защита от повторных запросов использует память Node.js. Для нескольких инстансов и serverless нужен внешний rate limiter (Redis/платформа), желательно с CAPTCHA или иным подтверждением при необходимости.
- Определение IP и происхождения запросов зависит от доверенного прокси/хостинга; дополнительно ограничивайте трафик средствами платформы.
- Подтверждение HTTP 2xx от вебхука не гарантирует последующую обработку в CRM. Для критичных заявок требуется очередь/хранилище и ретраи.
- Настройте наблюдение за сбоями, тесты доставки и контроль дублирования.
- Страница /privacy — **черновик**. Укажите настоящего оператора персональных данных, контакты, сроки хранения, получателей и правовое основание; проверьте требования России/Беларуси перед сбором реальных данных.
- Не публикуйте реальные контакты и цены без подтверждения владельца проекта.

## Быстрая проверка

```powershell
git pull origin main
npm run build
npm run dev
```

Откройте /contact и /pricing. Тест без настроенного URL должен возвращать понятную ошибку, не успех. Тест с реальным endpoint должен подтвердить фактическое получение заявки.
