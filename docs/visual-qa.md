# KODERA — визуальный и функциональный контроль

## Изменения текущего этапа
- Основные услуги (6): сокращён повторяющийся процессный блок; обновлены CTA, ссылки, canonical и соседние направления. Подтверждённые цены и кейсы не добавлялись.
- Решения (44): сохранились тематические страницы, визуальные акценты и интерактивный бриф. Каталог дополнен визуальными входами в три семейства услуг, алфавитной сортировкой и сбросом.
- Журнал (21): тематические обложки карточек и страниц, визуальные рекомендации, копирование URL, печать.
- Калькулятор: живой условный диапазон трудоёмкости с раскладкой по видам работ, шаговым управлением количеством экранов, сбросом и передачей параметров в обращение.
- Сайт: фирменная 404, правила печати, дополнительные проверки в scripts/audit.mjs.

## Проверка перед публикацией
```powershell
git pull origin main
npm run check
npm run dev
```

### Сценарии для ручной проверки
1. Шесть `/services/[slug]`: проверить изображения, ссылки на форму и калькулятор, раскрытие FAQ.
2. `/solutions`: поиск, категории, сортировка и сброс; открыть несколько из 44 направлений.
3. `/blog`: поиск, фильтры, изображения; внутри статьи проверить содержание, якоря, копирование ссылки и печать.
4. `/pricing`: менять страну, тип, экраны и дополнения; проверить сброс и передачу в `/contact`.
5. Ширины 375px, 768px, 1280px: горизонтальный скролл, читаемость текста, касания и обрезание визуалов.
6. Неверный адрес: фирменная 404.
7. Проверить Network/Console: ошибки загрузки изображений и клиентского JS.

### Блокеры реального коммерческого запуска
- Передача заявок через webhook/CRM ещё требует настройки и проверки фактического получения.
- Юридические сведения для страницы о персональных данных нужно утвердить для реального оператора.
- Для России и Беларуси требуется согласованный действующий прайс.
- Внешние изображения следует проверить на лицензию, стабильность и по возможности сохранить как собственные оптимизированные файлы с правами использования.
- Проводить финальную проверку Core Web Vitals на опубликованном сайте и устройствах.

## Уровень подтверждения
Проверка структуры GitHub не равна успешному `npm run build` и браузерному тестированию. Результат этих команд должен быть зелёным до признания релиза готовым.
